Working with Egregore

A guide to sessions, shared memory, coordination, and repository work.

Egregore gives each session access to the organization’s current work and durable memory. You open an instance, read its present state, describe the task, save the result, and hand it onward when another person should continue. The agent handles the underlying Git operations.

01 · Begin

A session opens on the organization’s present

The launcher prepares the instance before the agent begins. It synchronizes shared state, checks the workspace, and renders a startup card with the work that can shape your next move.

The card shows your identity and current branch alongside recent momentum, addressed handoffs, open questions, and service health. You then state what you want to do. A concrete work request gives the agent enough information to create a topic branch and focused worktree.

02 · Activity

Activity turns shared traces into an agenda

The startup card gives a compact signal. Activity opens the fuller team view, organized around work that may require your attention.

Running activity refreshes shared memory, reads the current repository state, and gathers addressed handoffs, pending questions, recent sessions, and open work. Connect adds relationship and status data from the organization graph. The result remains useful from Git-backed files in OSS.

03 · Workspace

Your workspace has a stable center

The Egregore repository is where sessions begin. Shared memory and selected code repositories live beside it as independent Git checkouts.

The Egregore repository holds the organization’s settings and the agent workflows available in the workspace. Its memory/ path points to a separate memory repository, giving every branch and worktree the same route to decisions, handoffs, questions, and findings.

04 · Repositories

A repository is cloned once

Selecting repositories during setup defines the workspace available to your agents. Egregore first checks the sibling directory where that repository would live.

An existing checkout is reused in place. A missing checkout is cloned beside Egregore. Later launches fetch its current state, so the normal session path uses the repository already present on your machine.

05 · Branches

Work begins away from main

New Egregore installations use main as the base branch. After you state a concrete task, the agent creates a working branch and performs the task inside its worktree.

The branch appears because Egregore protects the shared base from unfinished work. Existing organizations retain the base branch already stored in their settings. Teams that use a release stage can choose develop as the integration branch.

06 · Save

$save routes each change home

Saving is the user action that turns session work into durable Git history. Egregore scans the workspace, groups changed files by repository, and follows the correct path for each group.

Code and settings produce commits on their working branches, followed by pull requests to the configured base. Memory records commit through the memory repository’s own path. A task that changes several code repositories creates a separate pull request for every affected repository.

07 · Handoff

A handoff gives the next session an entry point

A handoff captures work for a named person or future session. It records the claim, current state, unresolved threads, and the place where work should resume.

Egregore writes the handoff into shared memory and gives it a durable identity. The receiver sees it through startup or activity, then claims the continuation. Repository and branch references travel with the record, allowing the next session to recover the relevant working state.

Universal Address the continuation

09 · Control

The CLI keeps every action close

Natural language is the common interface across agent runtimes. Shortcuts make repeated actions faster, while the launcher settings panel changes the instance itself.

Open the launcher with egregore and press s on the selected instance to manage hosted artifacts, repositories, administrators, and people. Direct settings commands expose the same changes for scripted use.
